# RTX 4060 / CPU 对照检查记录（2026-10-16）

这是已撤下的单环境 CUDA 采集路径的测量记录。当前仓库不再提供 `--physics-backend warp`。采集使用 CPU MuJoCo。下面的 GPU 命令和通过项对应当时的代码，不能在当前入口复现。

当时的结论：**部分配置能完成 GPU 采集，但 GPU 不能替代 CPU，也没有达到实时。** 同机 CPU 在轻量抓方块上快于实时，喂食物理和带相机的完整录制没有达到实时。

## 控制、观测与相机管线迁移（本次）

此前 `eeb0474` 只将喂食的逐步头部力统计移到 GPU，仍每个采样周期完整导出状态。本次把默认 IK/PD 路径作为整体修改：原 DLS 逆运动学、关节 PD、限时扰动、连续物理步、磁场／极分解／体积诊断、接触力和滑移、TCP 速度、任务几何评分和成功保持状态在 CUDA 执行。控制周期使用一张 CUDA Graph，既不减少 500 µs 物理步，也不降低 100 Hz 采样率。CPU 镜像只下载观测／绘图字段和接触力，不再导出质量矩阵、约束 Jacobian 和 flex Hessian；显示不再重复 CPU `mj_forward`。

场景相机新增显式 `--camera-backend warp`：官方 MuJoCo Warp 渲染器直接读取 CUDA 状态，三路相机共用渲染 Graph。默认仍为原 OpenGL；光线追踪与 OpenGL 不逐像素等价，元数据和数据目录区分二者，TACTO／FOTS／GelSight 来源光学模型未替换。Warp 无命中深度为 0，保存其原值并标记无效，不填成假深度。相机 Graph 准备放在录制计时前；图像渲染、下载、编码、写盘仍计入录制耗时。

CPU 保留初始化／复位、操作输入、格式组织、电子响应小向量运算、部分来源光学预后处理和文件输出；可选 Cartesian 控制、自定义逐步回调仍走 CPU 反馈兼容路径。喂食 IK 奇异值诊断仍使用 CPU。这里没有宣称整个程序不再执行 CPU 代码，或所有模式已经实时。

### 采样循环耗时定位

最终代码在同一 4060 主机测量 200 个 100 Hz 微动作样本（2 秒仿真），另生成 60 帧 640×480 单视角 OpenGL 预览；不写盘、不生成触觉 HUD。所有案例的监测都发现其他 GPU 计算进程，因此这是共享机器的耗时定位，**不是独占 GPU 性能上限，也不是用户 Mac 的人工遥操作验收**。

- tacto 抓方块：CPU 总耗时 0.376 秒，GPU 3.719 秒；GPU 控制周期中位数／P95 为 17.76／21.45 ms，CUDA 区间累计 3.064 秒。
- tacto 喂食：CPU 总耗时 4.036 秒，GPU 3.237 秒；GPU 控制周期中位数／P95 为 15.32／19.23 ms，CUDA 区间累计 2.910 秒。
- anyskin 抓方块：CPU 总耗时 1.454 秒，GPU 9.584 秒；GPU 控制周期中位数／P95 为 47.60／48.67 ms，CUDA 区间累计 9.224 秒。
- anyskin 弹性 single-clip：CPU 总耗时 2.056 秒，GPU 15.312 秒；GPU 控制周期中位数／P95 为 75.89／79.90 ms，CUDA 区间累计 14.904 秒。

CUDA Event 区间包括连续物理步、末态 forward、触觉和评分，不含 IK、下载和渲染；共享 GPU 的调度等待也会进入事件耗时，不能将它全称作独占内核计算时间。这轮即使不落盘也未全部实时，且大部分墙钟落在 CUDA 区间。继续只改缓存落盘或缩小 CPU 镜像，不足以据此承诺所有任务实时；仍需处理单环境求解成本、接触一致性，并在空闲 GPU 上完成实时遥操作验收。

## 前次喂食逐步读回修复与完整复验（eeb0474）

CPU 后端仍保留且为默认：省略 `--physics-backend` 或指定 `cpu` 都执行原生 MuJoCo；只有显式指定 `warp` 才加载 GPU 适配。该次性能修复仅修改 `core/gpu/backend.py`，没有修改 CPU 推进、采样率、材料或接触参数。

旧 GPU 喂食路径为沿用 CPU 的头部接触统计，每个 500 µs 物理步都完整导出 `MjData`，每个采样周期末又导出一次，即每仿真秒 2100 次。独占机器的固定姿态性能定位中，1 秒仿真耗时 14.12 秒；其中完整下载调用累计 13.45 秒，包含等待 GPU 完成、数据传输和 CPU 格式转换，不能全部称作传输耗时。CPU 接触统计本身仅 0.044 秒。

该版本用 Warp 官方 `contact_force` 提取力，原有总力、净力、逐步峰值和冲量统计在 GPU 中完成；每个 100 Hz 周期完整读回一次状态及七个统计量。默认 IK/PD 喂食的完整状态读回因此降为每仿真秒 100 次。最终代码同样的 1 秒固定姿态测量耗时 2.25 秒，实际计数为 100 次完整读回；这是性能定位，不是完整任务验收。保留原单步 CUDA Graph；需要 CPU 逐步反馈的其他控制模式仍走原兼容路径。

完整复验在同一台 4060 主机顺序运行，均使用原 `record-auto --task feeding` 控制器、seed 0、100 Hz 状态、30 Hz 三路 640×480 RGB-D 和双指触觉图像。记录位于 `data/gpu_acceptance_20261016/feeding_*`，不进入 Git。

- TACTO / 原 CPU 配置：任务成功，9.96 秒仿真、42.88 秒录制，0.232 倍实时；目录 `feeding_cpu_reference_tacto`。

四份完整记录均通过 LeRobot 官方加载、全部视频帧数、深度与状态时间戳检查；三份 GPU 记录的逐帧光学接触力与同刻原始值最大误差均为 0，CPU 记录为浮点舍入量级。此次 Mac 97 项单元测试、4060 的 12 项 GPU 基础／实际录制回归通过；新增检查覆盖前后头部接触、无接触时归零、净力符号、逐步峰值／冲量、复位，以及每个采样周期仅一次完整读回。摘要保存在同目录的 `feeding_readback_fix_validation.json`。

这里的“录制耗时”包含仿真、观测、图像生成、原始视频编码、状态／深度／触觉写盘以及关闭原始文件，不含启动准备、GPU 编译和随后 LeRobot 转换。CPU/GPU 的完整命令墙钟分别约 78.63 / 98.91 秒，另含这些准备及转换阶段。不能将录制耗时当作纯物理求解耗时，也不能直接与其他机器、其他相机／存储配置的实时采集比较。

“读回 CPU”指显存到内存的数据传输，“落盘”指将内存里的数据保存到文件，两者不同。在 eeb0474 中，CPU IK、部分评分／触觉处理和原 MuJoCo 场景更新接口仍消费每个采样周期的状态；把写盘延后不能消除这些同步。相机实际由 GPU/OpenGL 渲染，但尚未实现 Warp 状态到渲染器的直接设备传输。该次尚未迁移这些接口，也未新增异步写盘；本次迁移范围见本文首节。

该次消除了喂食的一个主要同步瓶颈，但 GPU 完整录制仍慢于 CPU、没有达到实时；任务成功也不等于此前的 CPU/GPU 触觉力差异已解决。
