# RTX 4060 / CPU 对照检查记录（2026-10-16）

当前结论：**部分配置能完成 GPU 采集，但 GPU 尚不能整体替代原 CPU 实现，也没有达到实时。** 原绳子弹性力迁移通过独立对照；接触求解、完整任务和数据链路分别验收，不能互相替代。安装与入口见 [GPU 采集说明](GPU_COLLECTION_ZH.md)。

## 环境与范围

- Mac：Python 3.12、MuJoCo 3.15.0，原生 CPU 默认后端。
- Linux：i5-14500、RTX 4060 8 GiB，正式 Git 克隆 `/home/dong/Projects/WowSkin-Lab`，独立 `.venv`；MuJoCo / MuJoCo Warp 3.15.0、Warp 1.18.0，EGL 无窗口渲染。
- GPU 组使用 CUDA Graph，绳子采用本地原插件力学移植，指腹仍是原 trilinear 模型。没有 MPM，也没有 GPU 出错后改用 CPU 推进。
- GPU 与 CPU 的短轨迹对照采用相同显式兼容选项：关闭 MULTICCD、NATIVECCD、额外 no-slip，超过 60 自由度使用稀疏 Jacobian。原版本默认碰撞选项的差异另行说明，不能称为完全相同的接触解。

## 基础检查与原 CPU 回归

- Mac 和 4060 主机：各 97 项单元测试通过。默认 CPU 路径不导入 Warp。
- 原 CPU 物理组全量运行 110 项；补齐 Pollen 资源、将 FOTS 来源对照固定为与适配器相同的 CPU 算术后，相关失败重测通过。仍有 1 项 Robotiq 强夹线在 t=3.420 s 触发原指腹翻转（Linux 最小体积比约 -0.729 / -0.675），并非 GPU 移植修复了原模型。
- FOTS 初次来源对照在 NVIDIA 上自动采用 CUDA，而适配器 MLP 使用 CPU：2.11% RGB 通道差 1 个灰度级。现对照同一设备，仍要求逐像素相等，没有放宽容差。
- Mac：6 项实际光学／LeRobot 录制回归通过，包括追加、失败保护、格式契约。
- 4060 主机：21 项官方数据流程回归全部通过（387.26 秒），覆盖 LeRobot、ViSk 原转换器／加载器、FTF 原写入／预处理、来源配置及 DDQN 源方法检查；这些数据接口测试仍按原 CPU 物理运行，不算 GPU 动力学对照或正式策略训练。
- 已下载的 Pollen 检查点／公开数据两项回归通过。可选 ReSkin 正逆模型、通道映射模型、伪标签实验产物不在新机器上，artifact 组报告 8 条跳过记录（含一个类初始化跳过）；没有把跳过计作通过，也未为了通过测试另行训练这些模型。
- 4060：10 项 GPU 基础测试通过（`test_cable`、`test_environment`、`test_recording`）。其中覆盖多个参数子案例，并非只运行 10 个物理状态。
- 绳子：胶囊／盒形截面、flat 两种参考设置，共四组，检查原 CPU 插件受力、200 步轨迹和直接执行／Graph 对照；项目 single-clip 与 routing 原始模型也核对弹性力。力误差允许 `rtol=2e-4, atol=2e-6`，轨迹位置允许 `rtol=1e-3, atol=2e-5`；不把其他 flex 的浮点差异当作绳子移植误差。
- 控制／状态：运动时刻、重复复位、显式故障要求复位、没有正常采样期间的 CPU `mj_step`／活状态 `mj_forward`，以及原生一步／GPU、GPU 直接／Graph 对照。
- 读数：两块软垫的接触索引范围；纯刚体接触不得误标成 flex；四种传感器实际写入三路 RGB-D、状态。三种光学触觉使用已经夹持勺子的实际受力状态，逐帧核对光学接触力与同刻原始读数，再生成离线回放；这些短测试不贴成功任务标签。另将 AnySkin 及三种光学受力场景的 CPU 接触读回，与 Warp 原生 `contact_force` 内核直接逐接触核对全部六维力／矩（`rtol=1e-6, atol=1e-7`），均通过，避免两个 CPU 读数共用同一个错误。

## 扩展任务对照的未通过项

`tests.gpu.test_tasks` 覆盖 Panda 四种传感器 × 六种任务／布局，以及 Robotiq 五种原 AnySkin 配置。四种薯片配置验证明确拒绝 GPU；其余 25 种执行 10 个采样周期（0.1 秒）的微小实际运动。

判断条件包括：`qpos` 分量绝对误差不超过 0.002、TCP 坐标误差不超过 0.2 mm、双指法向力 `rtol=0.1, atol=0.05 N`，时钟一致且无溢出。`qpos` 混合平移、转角与四元数分量，其最大误差不能统一解释为米。

最后一轮有 **16 种通过，5 种差异超限，4 种因迭代上限中止**。这些失败保留为可复现检查，没有扩大容差或标成跳过：

- 差异超限：Panda AnySkin 喂食、TACTO 喂食、FOTS 喂食、TACTO Peg、FOTS Peg。部分小接触对初始状态／浮点归约敏感，重复运行可改变边界案例是否刚好越过容差，因此不能按单次成功宣布稳定等价。
- 迭代上限：Panda AnySkin Peg；Robotiq routing、喂食、Peg。Robotiq routing 在先前一轮短测试通过，后续轮次达到上限，仍归为未稳定验收。
- TACTO Peg 的一轮结果：物体位置相差约 1.15 mm；GPU 两指约 17.6 / 18.7 N，CPU 约 29.8 / 93.1 N。机器人 TCP 接近并不足以说明触觉力一致。
- FOTS 喂食的一轮结果：GPU 约 0 / 0.357 N，CPU 约 0.826 / 0.478 N；虽然物体位置相差约 0.14 mm，触觉力仍不满足对照要求。

AnySkin 抓方块完整规则轨迹也未通过：来源 30 次迭代、显式 100 次迭代，以及 100 次配合 `1e-6` 容差均在接触过程中达到上限。达到上限不等于已翻转，但本后端按保守采集规则中止，不导出为成功示范。

薯片 GPU 动态断裂尚未迁移：碎片分离后碰撞掩码需要重建，GPU 读回的稀疏约束索引也不能沿用原缓存。当前在创建 GPU 后端时明确报错，继续使用 CPU；不会跑一份不同的断裂行为。

## 完整数据链路

修复前的 GPU 光学样例已作废：Warp 的旧接触字段会导致 TACTO 漏渲染接触、FOTS marker 接触状态错误；纯刚体接触还可能误标成 flex，影响方块释放评分。格式检查通过不代表这些旧样例的触觉语义正确，不应训练使用。

最终重录使用来源 CPU 设置复位，再显式应用 GPU 兼容选项；不沿用上轮 GPU 设置初始化。记录保存在 4060 的 `data/gpu_acceptance_20261016/`，不进入 Git。完整任务按原评分判定，不手工贴成功标签。

- TACTO 抓方块：成功；1232 个 100 Hz 样本、370 帧；采集 12.31 秒仿真耗时 42.27 秒（0.291 倍实时），最大求解迭代 8 次。
- FOTS 抓方块：成功；1232 个样本、370 帧；采集耗时 64.92 秒（0.190 倍实时），最大迭代 18 次。
- GelSight 抓方块：成功；1232 个样本、370 帧；采集耗时 47.15 秒（0.261 倍实时），最大迭代 17 次。
- TACTO 喂食（逐步读回修复前）：成功；1002 个样本、301 帧；10.01 秒仿真采集耗时 168.33 秒（0.0595 倍实时），最大迭代 13 次。官方读取／离线回放通过，双指光学力与原始值逐帧一致，最大压痕约 0.244 mm。这仍是现有到嘴前目标区评分，不代表吞咽或接触安全实验。修复后的完整复验见下节。
- TACTO 弹性 single-clip：未成功；完整运行 18.81 秒仿真，1882 个样本、565 帧，无溢出、最大迭代 10 次，但线仅穿过三个评分截面中的一个，未导出 LeRobot 成功示范；验收摘要保留，失败大文件已清理。
- 同一规则控制器的完整 CPU 对照（同种初始化、60 步预滚、不渲染／写盘）：来源默认设置在第 1232 个任务采样达到成功，三个截面全部满足；CPU 改为 GPU 相同的兼容接触选项后，1800 步未成功，仅两个截面满足。因此兼容设置本身就足以改变任务结果，不能仅凭绳子弹性力公式对照通过便宣称整条绳子任务与原实现一致；此对照没有单独归因到某一个选项。
- 三种抓方块记录均通过 LeRobot 官方读取、视频／深度检查及离线 HTML / MP4 回放。每帧光学接触力与同刻 100 Hz 原始值一致（误差 0）；双指最大光学压痕约为 TACTO 0.321 mm、FOTS 2.276 mm、GelSight 2.284 mm。各来源传感器和成像模型不同，这些数值不表示三种硬件真实压痕应当相同。

这些都是读取仿真物体位姿的规则示范，非 agent 推理、人工示范或策略训练成功率。任务成功也不证明 CPU/GPU 接触力等价。采集耗时包括图像生成／写盘，不含 GPU 编译和 LeRobot 打包；本轮同时有 CPU 数据链路回归，耗时仅代表该轮运行条件。

## 喂食逐步读回修复与完整复验

CPU 后端仍保留且为默认：省略 `--physics-backend` 或指定 `cpu` 都执行原生 MuJoCo；只有显式指定 `warp` 才加载 GPU 适配。此次性能修复仅修改 `core/gpu/backend.py`，没有修改 CPU 推进、采样率、材料或接触参数。

旧 GPU 喂食路径为沿用 CPU 的头部接触统计，每个 500 µs 物理步都完整导出 `MjData`，每个采样周期末又导出一次，即每仿真秒 2100 次。独占机器的固定姿态性能定位中，1 秒仿真耗时 14.12 秒；其中完整下载调用累计 13.45 秒，包含等待 GPU 完成、数据传输和 CPU 格式转换，不能全部称作传输耗时。CPU 接触统计本身仅 0.044 秒。

现在用 Warp 官方 `contact_force` 提取力，原有总力、净力、逐步峰值和冲量统计在 GPU 中完成；每个 100 Hz 周期完整读回一次状态及七个统计量。默认 IK/PD 喂食的完整状态读回因此降为每仿真秒 100 次。最终代码同样的 1 秒固定姿态测量耗时 2.25 秒，实际计数为 100 次完整读回；这是性能定位，不是完整任务验收。保留原单步 CUDA Graph；需要 CPU 逐步反馈的其他控制模式仍走原兼容路径。

完整复验在同一台 4060 主机顺序运行，均使用原 `record-auto --task feeding` 控制器、seed 0、100 Hz 状态、30 Hz 三路 640×480 RGB-D 和双指触觉图像。记录位于 `data/gpu_acceptance_20261016/feeding_*`，不进入 Git。

- TACTO / GPU：任务成功，10.01 秒仿真、59.08 秒录制，0.169 倍实时，最大求解迭代 13 次；目录 `feeding_readback_fix_tacto`。
- TACTO / 原 CPU 配置：任务成功，9.96 秒仿真、42.88 秒录制，0.232 倍实时；目录 `feeding_cpu_reference_tacto`。
- FOTS / GPU：任务成功，9.88 秒仿真、93.87 秒录制，0.105 倍实时；目录 `feeding_readback_fix_fots`。
- GelSight / GPU：任务成功，9.88 秒仿真、60.86 秒录制，0.162 倍实时，最大求解迭代 17 次；目录 `feeding_readback_fix_gelsight`。

四份完整记录均通过 LeRobot 官方加载、全部视频帧数、深度与状态时间戳检查；三份 GPU 记录的逐帧光学接触力与同刻原始值最大误差均为 0，CPU 记录为浮点舍入量级。此次 Mac 97 项单元测试、4060 的 12 项 GPU 基础／实际录制回归通过；新增检查覆盖前后头部接触、无接触时归零、净力符号、逐步峰值／冲量、复位，以及每个采样周期仅一次完整读回。摘要保存在同目录的 `feeding_readback_fix_validation.json`。

这里的“录制耗时”包含仿真、观测、图像生成、原始视频编码、状态／深度／触觉写盘以及关闭原始文件，不含启动准备、GPU 编译和随后 LeRobot 转换。CPU/GPU 的完整命令墙钟分别约 78.63 / 98.91 秒，另含这些准备及转换阶段。不能将录制耗时当作纯物理求解耗时，也不能直接与其他机器、其他相机／存储配置的实时采集比较。

“读回 CPU”指显存到内存的数据传输，“落盘”指将内存里的数据保存到文件，两者不同。当前 CPU IK、部分评分／触觉处理和原 MuJoCo 场景更新接口仍消费每个采样周期的状态；把写盘延后不能消除这些同步。相机实际由 GPU/OpenGL 渲染，但尚未实现 Warp 状态到渲染器的直接设备传输。此次未迁移这些接口，也未新增异步写盘。

此次消除了喂食的一个主要同步瓶颈，但 GPU 完整录制仍慢于 CPU、没有达到实时；任务成功也不等于此前的 CPU/GPU 触觉力差异已解决。

## 本轮修复与清理

- 将 GPU 物理和绳子力学迁入正式 `wowskin_lab/core/gpu`，共用 `env.step`／录制入口；安装选项进入 `scripts/setup_capture.py --gpu`。
- 修正 Warp 全局 flex 单元／顶点编号向原 CPU 读数局部编号的转换，避免右指腹接触越界。
- 修正光学渲染的接触 geom 读取；补齐刚体读回的 `flex/elem/vert=-1`，避免把桌面接触误认为夹爪仍抓住方块。
- 修正 EGL 双指显示连接的生命周期，关闭一个 TACTO 渲染器不会破坏其他渲染器。
- 回放、LeRobot 重打包以及 ViSk／FTF 转换均使用 PyAV 解码，解决 Linux OpenCV 无法解码 LeRobot AV1 视频的问题。
- 原始记录保存 GPU 参数、诊断和中断原因；状态时间戳按实际物理步计数；每次复位还原来源求解设置，再显式应用 GPU 选项。
- 删除重复的 GPU 诊断运行入口，以及本机旧 MPM / 全 GPU 绳子试验源码和输出；保留正式实现、来源许可证、必要回归测试与本记录。正式采集数据不入 Git。远端额外删除旧 MPM 工作区及修复前无效 GPU 样例约 2.6 GiB。

仍需完成：AnySkin 强接触收敛、光学 Peg／FOTS 喂食的接触力差异、薯片动态断裂、剩余 CPU/GPU 观测同步及录制开销，以及真实桌面键盘／外设交互的 GPU 人工验收。当前没有重新验证策略训练效果。
